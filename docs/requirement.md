# 要件

> ステータス: 主要な機能は実装済み。未実装の機能は「未実装」の節にまとめる。DB 設計は [database.md](./design/database.md)、画面設計は [screens.md](./design/screens.md)、ユーザーストーリーは [user-stories](./user-stories/) を参照。

## コンセプト

Wikipedia の記事を1枚のカードにしたトレーディングカードを、パックを開けて集めるアプリ。
開封の演出はポケポケ（Pokémon TCG Pocket）並みの豪華さを目指す。

## カード

- カードは Wikipedia の記事1ページを元に作る。
  - 表に出す情報は、記事タイトル、要約（冒頭の一文〜数文）、画像、属性アイコン、月間閲覧数。
  - カード詳細の名前の右側に、記事を新しいタブで開くアイコンリンクを載せる。リンクの文字、出典・ライセンス・版・画像クレジットの行は表示しない。
  - 画像がないカードは、ジャンルの色とタイトルの1文字目で絵柄を描く。
- レアリティは記事の閲覧数で決める。
  - 閲覧数の dump から直近1か月（今月を除く）の閲覧数を数え、5段階に振り分ける。12か月分の dump を読むと数時間かかるため、1か月にしている。`--months` で月数を増やすと、その月平均で数える。
  - 最初の取り込みで、上位 10 万件の一覧のなかの順位（下の表）から各レアリティの閲覧数の下限を決める。あとから足すカードは、その下限で判定する。取り込むたびに順位で決め直すと、同じ閲覧数でも取り込んだ時期によってレアリティが変わってしまうため。
  - レアリティはカードを作った時点で固定し、その後の閲覧数の変化では変えない。マーケットでの価値が勝手に変わらないようにするため。
- 各カードは1つのジャンルに属する。ジャンルは記事に紐づく Wikidata の「分類」（instance of、P31）をそのまま使う（例: 人間、山、テレビアニメ）。こちらでジャンルを決めたり、まとめたりはしない。
  - 分類が複数ある記事は、推奨ランクのものを、同じランクなら Wikidata の ID の数字が小さいものを選ぶ。
  - ジャンルの名前は分類の日本語ラベル。初めて出てきたときの名前で固定する。
  - 分類がない記事と、分類に日本語ラベルがない記事はカードにしない。
  - ジャンルの色は Wikidata の ID から機械的に決める。
- 日本語版の記事だけを扱う。

| レアリティ | 表示 | 閲覧数の順位 | 還元ポイント |
| ---------- | ---- | ------------ | ------------ |
| コモン     | ◇    | 下位 50%     | 1pt          |
| アンコモン | ◇◇   | 上位 20〜50% | 3pt          |
| レア       | ◇◇◇  | 上位 5〜20%  | 15pt         |
| ダブルレア | ◇◇◇◇ | 上位 1〜5%   | 60pt         |
| レジェンド | ☆    | 上位 1%      | 300pt        |

## カードの取り込み

- 日本語版 Wikipedia の直近1か月の閲覧数の上位 10 万件を集め、上から順にカードにする。
  - 閲覧数は Wikimedia の閲覧数の dump（月次、人による閲覧だけ）から数える。`bun run wiki:top` で上位の一覧を作る。
  - `bun run wiki:import --limit <n>` で、一覧の上からまだ調べていない記事を n 件ずつ調べてカードにする。いまはローカルから実行する。
- 取り込んだカード、ジャンル、除外した記事、レアリティの下限は、JSONL のファイルにして git で管理する（`packages/wiki-import/data/ja/`）。差分を確かめてからコミットし、`bun run wiki:load` でローカルの D1 に入れる。動作確認は同じ DB を使う `bun run dev:local` で行う。
- 人の確認ははさまず、次の記事は自動で除外する。外し漏れたカードは、あとから排出を止める。
  - 記事以外のページ（利用者ページ、Wikipedia の運営のページ、メインページなど）
  - 曖昧さ回避のページと、一覧記事
  - 事件・事故・災害などの記事。被害者のいる出来事にレアリティを付けないため
  - 要約が短すぎる記事
  - Wikidata の分類がない記事
- 要約は記事冒頭の要約（REST API の `extract`）をそのまま使う。
- 画像は Wikimedia Commons にあるフリーライセンスの画像だけを使い、作者とライセンスを元データに保持する。
  - `bun run wiki:images` で取得済みの画像 URL から画像を R2 に保存する。JPEG・PNG・WebP・GIF・AVIF の10MiB以下が対象で、SVG は保存しない。
  - 保存済み画像は本サービス経由で配信し、未保存の画像は元の Wikimedia URL から読み込む。元 URL と作者・ライセンスは保持する。
  - 同一 URL の画像は重複保存しない。ローカル R2 と本番 R2 への保存を選べる。
- 存命の人物の記事もカードにする。本人や権利者から申し出があれば、そのカードの排出を止める（JSONL の `isActive` を false にして D1 に入れ直す）。所持済みのカードは残る。
- すでにカードになっている記事と、除外した記事は取り直さない。要約、版、ジャンル、レアリティは取り込んだ時点のまま固定する。
- 取り込みの詳しい手順は [database.md](./design/database.md) の「Wikipedia からのカード作成」を参照。

## 共通レイアウト

- カードの画像は角丸の正方形で表示する。枠やホログラムは重ねず、タイトルを画像の下に置き、属性アイコンをタイトルの左側に表示する。ジャンル名は表示しない。小さなサムネイルは画像だけを表示する。画像がない場合や読み込めない場合は、ジャンルの色とタイトルの先頭文字で表示する。

- ヘッダーとボトムタブの白背景は画面の横幅いっぱいに表示し、中身と本文は中央の最大 28rem 幅に収める。
- ヘッダーと本文の間には最低 16px の余白を置く。
- カード詳細（`/cards/:cardId`）のヘッダーは、通常表示・エラー表示ともに「Wiki Collection」を表示せず、もどるボタンと残高を表示する。
- ボトムタブは画面下端に固定し、長いコレクションのスクロール中も表示する。本文の末尾にはタブに隠れない余白を確保する。開封演出中は非表示にする。
- 選択中のボトムタブは青いアイコン・文字と薄い青の背景で区別する。検索条件や配下の画面でも選択を維持する。

## パック

1パック5枚入り。パックは複数あり、ユーザーは好きなパックを選んで開封できる。

パックの外観は、上下に圧着線のある金属光沢の箔袋とする。表面には「WIKI COLLECTION」と本のアイコンを表示し、選択・詳細・開封の各画面で共通のデザインを使う。袋の表面にはパック名を表示しない。

- 基本パック
  - 全ジャンルのカードから出る。レアカードの排出率は低い。
  - 登録日から毎日10パックを無料で開封でき、日本時間の毎日0時に枠がリセットされる。持ち越せないため、3日開けなくても使えるのはその日の10パックだけ。
  - 登録特典は付与しない。既存の登録特典残高も利用対象にしない。
- ジャンルパック（例: 「人間パック」「天体パック」）
  - 特定のジャンルのカードだけが出る。パックごとに指定した注目カードが出やすい。
  - pt を払って開封する（150pt）。
- パック選択画面で中央のパックをタップすると、詳細画面や確認ダイアログを挟まずに開封画面へ進む。有料パックは一覧に消費 pt と残高を表示し、タップ時に pt を消費する。
- 排出率はパックごとに、枠（何枚目か）とレアリティの組み合わせで設定し、パック選択画面で公開する。

## 当たったカードの使い方

- ポイント還元: カードを手放して、レアリティに応じた無償 pt を受け取る。重複したカードは、各カードを1枚ずつ残してまとめて還元できる。
- マーケット出品: 次のどちらかの形式で、ほかのユーザーに pt で売る。
  - フリマ形式: 出品者が決めた価格で、最初に買った人が購入できる。
  - オークション形式: 開始価格と期間（1日・3日・7日）を決め、終了時点で最高額の入札者が落札する。入札額は入札した時点で支払い、抜かれたら返す。
- 取引が成立すると、成立価格から手数料 10%（1pt 未満切り捨て）を引いた額が、無償 pt として出品者に入る。
- 入札のあるオークションは取り下げられない。

## 能力値・チーム・合成・対戦

- 基本攻撃力は取り込み時の月間閲覧数、基本防御力は記事ソースのバイト数。
- 各ページの能力値・強化値・対戦計算式・相性説明は、攻撃を剣、防御を盾のアイコンで表す。能力値のペアは改行せず1行で表示する。画面上に能力名の文字ラベルは表示せず、読み上げ用の名前を付ける。
- 属性は記事のWikidata分類から、人物・自然・社会・文化に割り当てる。記事IDの余りやランダムでは決めない。元のジャンルは分類データとして保持するが、カード情報には表示しない。
  - 人物は人間、自然は生物・天体・地形など、社会は国・企業・制度など、文化は映画・音楽・漫画・スポーツ・プログラミング言語・ウェブサービスなどに対応する。
  - 分類IDと属性の対応を共有コードで管理する。未対応の分類は「総合」とし、相性倍率を付けない。
  - 人物 → 文化 → 社会 → 自然 → 人物の方向に弱点を突き、攻撃力が2倍になる。それ以外は1倍。
  - カード情報では属性を名前の左側にアイコンだけで表示する。属性名は相性の説明内で表示する。押すと相性モーダルを開き、円形の相性図で4組の有利な方向と選んだ属性の有利・不利を確認できる。総合は倍率なし、過去の旧属性は当時の相性を表示する。
  - 相性は分野どうしのつながりを表現したゲームのルールで、現実の優劣を意味しない。
  - 科学技術は文化に統合する。新しい日次結果にはルールの版を保存する。
  - 科学技術を含む5属性時代や旧属性で保存された過去の対戦は「旧属性ルール」と明示して保持し、勝敗を変更しない。
- 所持カード3枚を順序付きで選び、1人3チームまで保存できる。同じ所持カードを複数チームに使える。
  - 一覧の追加・編集ボタンからシートで編成する。画像付き3列の一覧を押して3枚選び、選択順に上部へ固定表示する。選択解除と左右の順序交換に対応する。番手指定・検索・フィルター・自動編成は置かない。未保存で閉じる際は破棄を確認する。
  - 練習対戦はチーム一覧の各チームから独立したシートで利用する。編成シートには置かず、保存済みのチームでサンプルまたは最新結果の他プレイヤーの編成と対戦する。練習は消費・報酬・順位への影響がなく、相手は保存時点の状態を使う。旧属性の相手は練習候補に出さない。
- 編成中のカードは還元・出品・合成素材に使えない。強化するベースには使える。
- チーム一覧の各カード右側の上向き矢印（強化）または「所持カードを強化」からシートを開く。選択欄は画像付き3列で、検索・属性フィルター・並び順の操作は設けない。素材にできないカードは一覧に出さない。同種の未強化カードはまとめて所持枚数・素材に使える枚数を表示し、使用枚数を指定できる。強化済みは1枚ずつ別枠で選ぶ。複数種類の素材を選べ、「未強化をまとめて選択」は強化済みを除外する。最終確認には素材の能力値・強化済み量・種類別の枚数と合計枚数を表示する。強化後の目安や計算式の説明はシートに表示しない。
- 合成は素材を1〜50枚一括消費し、各素材の現在の攻撃・防御それぞれの1%に素材ごとの0.2〜1の一様ランダム係数を掛けてベースへ合計加算する。1枚でも使用不可なら消費・履歴・加算をすべて取り消す。ptは消費しない。
  - 小数を蓄積する。属性とレアリティは変えない。強化値は1枚ごとに保存し、売買後も引き継ぐ。
- 毎日日本時間0時に、別プレイヤーの全チームとの自動対戦を行う。本番はデプロイ後にCronが有効になる。
  - 同じ位置のカードの攻撃力から相手の防御力を引き（最低0）、ダメージの大きい側が勝つ。3組の勝ち数でチームの勝敗を決める。
  - 勝ち3点・分け1点・負け0点。対戦数に対する勝点率で日次順位を決め、同率は同順位。対戦報酬はない。
  - 次回開催時刻と参加予定チーム数を表示する。ランキングは自分のチームへの絞り込み、勝点率、対戦数と対戦ごとのダメージ内訳を確認できる。
  - 結果と当時の編成・能力値を保存する。再実行や編集で過去の結果は変わらない。
  - ニックネーム・チーム名・対戦時のカードと能力値・戦績を他のログイン利用者に表示する。
- 記事サイズが未計測の既存カードは補完まで編成・合成できない。画面には未計測と表示する。

## ゲーム内通貨（pt）

- 課金で購入できる（500pt $5、1,000pt $10、5,000pt $50）。
- 使い道は、有料パックの開封と、マーケットでのカード購入・入札。
- 課金で得た有償 pt と、還元や売上で得た無償 pt を区別する。資金決済法の前払式支払手段として有償分の未使用残高を管理するため。
- 残高は、獲得の記録（`coin_deposit`）と、消費をどの獲得分から払ったかの記録（`coin_deposit_withdraw`）から計算する。残高だけを持つテーブルは作らない。
- 支払いは無償 pt から先に、同じ種類なら古い獲得分から使う。
- pt を現金に払い戻す機能は作らない。

## 開封の演出

ポケポケの開封を参考にする。流れは次のとおり。詳細は [screens.md](./design/screens.md) の開封画面を参照。

1. パック選択（カルーセル）→「これにする」
2. パックが拡大して手前に来る
3. パックの上端を指でなぞって破る（光の線が走り、上部が飛び、画面が白く光る）
4. カードの束が出てきて、タップで1枚ずつめくる。NEW バッジ、レアリティのマーク、レア以上なら光の粒が出る。レジェンドの直前は束の縁が金色に光る
5. 最後に「開封結果」として5枚を一覧で表示する

抽選はサーバーで済ませてから演出を始める。演出の途中でリロードしても引き直しにはならず、開封履歴から続きを見られる。

## 法務・運営上の確認事項

- 資金決済法: 有償 pt は前払式支払手段にあたる。未使用残高が基準日に1,000万円を超えると届出と供託が必要。払い戻しは原則禁止。
- 景品表示法: 特定の組み合わせを揃えると報酬が出る仕組み（いわゆるコンプガチャ）は作らない。
- 排出率の表示: 業界ガイドライン（JOGA）に沿って、パックごとに排出率を表示する。
- 賭博にあたらないようにする: pt やカードを現金化できる経路（RMT）を利用規約で禁止し、払い戻しも行わない。
- Wikipedia のライセンス: 本文は CC BY-SA 4.0。カード詳細には記事へのアイコンリンクを載せ、要約テキストは同じライセンスで扱う。画像は記事ごとにライセンスが異なり、フェアユースの画像は使えないため、Wikimedia Commons のフリーライセンス画像だけを使う。
- 未成年の課金上限を設ける（規約には記載済み、機能は未実装）。
- 規約類のページ: 利用規約（`/legal/terms`）、プライバシーポリシー（`/legal/privacy`）、特定商取引法に基づく表記（`/legal/tokushoho`）、資金決済法に基づく表示（`/legal/payment-services`）。運営者名・住所・連絡先などは［］の仮置きで、公開前に埋めて法務確認を受ける。
