# 要件

> ステータス: 主要な機能は実装済み。未実装の機能は「未実装」の節にまとめる。DB 設計は [database.md](./design/database.md)、画面設計は [screens.md](./design/screens.md)、ユーザーストーリーは [user-stories](./user-stories/) を参照。

## コンセプト

Wikipedia の記事を1枚のカードにしたトレーディングカードを、パックを開けて集めるアプリ。
開封の演出はポケポケ（Pokémon TCG Pocket）並みの豪華さを目指す。

## 対応クライアント

- アプリの画面と読み上げラベルは日本語・英語に対応し、初期設定ではOSの優先言語に従う。マイページの「言語切り替え」で日本語・英語・端末の設定を選べる。記事は取り込んだ言語で表示する。→ [アプリの表示言語を切り替える](./user-stories/app-language.md)
- ゲームはiOS・Android向けのExpo / React Nativeアプリを `apps/native` に実装する。
- 起動時とバックグラウンドからの復帰時にOS別の最低対応バージョンを確認する。対象外の版には更新先を案内し、ゲームの利用には更新を必須とする。→ [旧バージョンからアプリを更新する](./user-stories/force-update.md)
- 初回は自動でゲストとして開始する。iOSではマイページからApple Accountに連携すると、再インストールや機種変更後も同じApple Accountで所持カード・残高・履歴を引き継げる。未連携でアプリを削除したゲストは復元できない。マイページからアカウントの削除を依頼できる。Webではゲーム画面・ログイン画面を提供せず、規約・法定表記とその一覧だけを公開する。
- ポイント残高の右にあるベル、またはマイページの「通知」から自分宛ての通知を新しい順に確認できる。本文を開くと、その利用者の通知だけが既読になる。未読が1件以上ある間はベルに赤い点を表示する。
- パック、コレクション、ランキング、マーケット、マイページの5タブで操作する。規約本文はWeb側だけで管理し、マイページとポイント購入画面からアプリ内ブラウザで開く。
- iOSのメイン5画面・詳細画面・開封結果にはOS標準タブを使い、iOS 26以降ではLiquid Glassで表示する。旧iOSはOS標準の従来表示、Android・開発用Expo Webは従来のカスタムタブを使う。
- iOSの購入はStoreKitに対応する。Google Playの実課金は未実装。

## カード

- カードは Wikipedia の記事1ページを元に作る。
  - 表に出す情報は、記事タイトル、要約（冒頭の一文〜数文）、画像、月間閲覧数。
  - カード詳細の名前の右側に、記事を新しいタブで開くアイコンリンクを載せる。リンクの文字、出典・ライセンス・版・画像クレジットの行は表示しない。
  - 画像がないカードは、ジャンルの色とタイトルの1文字目で絵柄を描く。
- レアリティは記事の閲覧数で決める。
  - 閲覧数の dump から直近1か月（今月を除く）の閲覧数を数え、4段階に振り分ける。
  - 保存した月間閲覧数に、次の固定基準を適用する。→ [レアリティを確認する](./user-stories/card-rarity.md)
  - レアリティはカードを作った時点で固定し、その後の閲覧数の変化では変えない。マーケットでの価値が勝手に変わらないようにするため。
- 各カードは1つのジャンルに属する。ジャンルは記事に紐づく Wikidata の「分類」（instance of、P31）をそのまま使う（例: 人間、山、テレビアニメ）。こちらでジャンルを決めたり、まとめたりはしない。
  - 分類が複数ある記事は、推奨ランクのものを、同じランクなら Wikidata の ID の数字が小さいものを選ぶ。
  - ジャンルの名前は分類の日本語ラベル。初めて出てきたときの名前で固定する。
  - 分類がない記事と、分類に日本語ラベルがない記事はカードにしない。
  - ジャンルの色は Wikidata の ID から機械的に決める。
- 日本語版の記事だけを扱う。

| レアリティ | 月間閲覧数 |
| --- | --- |
| レジェンド | 10万回以上 |
| SR（スーパーレア） | 5万回以上、10万回未満 |
| R（レア） | 1万回以上、5万回未満 |
| C（コモン） | 1万回未満 |

## カードの取り込み

- 日本語版 Wikipedia の記事ダンプから標準名前空間の全記事（転送ページを除く）を候補にする。先月の閲覧数がない記事も0回として扱う。
- 記事候補はR2に月ごとに保存する。本番D1のseedはローカルの記事候補JSONLを読み込む。
- 人の確認ははさまず、次の記事は自動で除外する。外し漏れたカードは、あとから排出を止める。
  - 記事以外のページ（利用者ページ、Wikipedia の運営のページ、メインページなど）
  - 曖昧さ回避のページと、一覧記事
  - 事件・事故・災害などの記事。被害者のいる出来事にレアリティを付けないため
  - 要約が短すぎる記事
  - Wikidata の分類がない記事
- 要約は記事冒頭の段落を使い、取得した版を記録する。
- 画像は Wikimedia Commons にあるフリーライセンスの画像だけを使い、作者とライセンスを元データに保持する。
  - R・SR・レジェンドは画像保存コマンドで、コモンは初めて引かれたときに R2 に保存する。JPEG・PNG・WebP・GIF・AVIF の10MiB以下が対象で、新規保存時にWebPへ変換する。容量は30〜50 KBを目安とし、小さい画像は30 KB未満も許容する。上限は50,000バイト。SVG は保存しない。
  - 保存済み画像は本サービス経由で配信し、未保存の画像は元の Wikimedia URL から読み込む。元 URL と作者・ライセンスは保持する。
  - 同一 URL の画像は重複保存しない。ローカル R2 と本番 R2 への保存を選べる。
- 存命の人物の記事もカードにする。本人や権利者から申し出があれば、そのカードの排出を止める（対象カードを D1 で無効にする）。所持済みのカードは残る。
- D1に登録済みのカードの要約、版、ジャンル、レアリティは取り込んだ時点のまま固定する。
- 取り込みの詳しい手順は [database.md](./design/database.md) の「Wikipedia からのカード作成」を参照。

## 共通レイアウト

- カードの画像は角丸の正方形で表示する。枠やホログラムは重ねず、タイトルを画像の下に置く。ジャンル名は表示しない。小さなサムネイルは画像だけを表示する。画像がない場合や読み込めない場合は、ジャンルの色とタイトルの先頭文字で表示する。

- iOSのメインタブの外観はOS標準に従う。以下のタブ背景・選択表示の指定はカスタムタブに適用する。
- ヘッダーとボトムタブの白背景は画面の横幅いっぱいに表示し、中身と本文は中央の最大 28rem 幅に収める。
- ヘッダーと本文の間には最低 16px の余白を置く。
- カード詳細（`/cards/:cardId`）のヘッダーは、通常表示・エラー表示ともに「Wiki Collection」を表示せず、もどるボタンと残高を表示する。
- ボトムタブは画面下端に固定し、長いコレクションのスクロール中も表示する。本文の末尾にはタブに隠れない余白を確保する。開封演出中は非表示にする。
- 選択中のボトムタブは青いアイコン・文字と薄い青の背景で区別する。検索条件や配下の画面でも選択を維持する。

## パック

1パック5枚入り。パックは複数あり、ユーザーは好きなパックを選んで開封できる。

パックの外観は、黒地に斜めの帯が入り、上下に圧着線のある箔袋とする。帯と圧着部は基本パックがオレンジ、SR1枚確定が銀色、レジェンド1枚確定が金色。表面には「WIKI COLLECTION」と本のアイコンを表示し、選択画面と開封画面で共通のデザインを使う。袋の表面にはパック名を表示しない。

- 基本パック
  - 全ジャンルのカードから出る。レアカードの排出率は低い。
  - 登録時は10パック分の無料枠があり、開封すると1回分を消費する。無料枠は10分ごとに1回分回復し、最大10回分まで貯まる。
  - 登録特典は付与しない。既存の登録特典残高も利用対象にしない。
- SR1枚確定ガチャは100pt。全ジャンルが対象で、1〜4枠は基本パックと同じ確率で抽選し、5枠目はSRが確定する。
- レジェンド1枚確定ガチャは500pt。全ジャンルが対象で、1〜4枠は基本パックと同じ確率で抽選し、5枠目はレジェンドが確定する。
- 確定ガチャは対象レアリティのカードが1枚もなければ開封できず、pt も消費しない。
- パック選択画面では無料パックのボタンは「無料で開封する」と表示する。有料パックのボタンはヘッダーと同じコインアイコンの横に「100pt で開封する」のように必要なポイントを表示する。ボタンを押すと開封し、有料パックではポイントを消費する。残高が足りない場合はモーダルからポイント購入画面に進める。ヘッダーのポイント残高の左にプレゼントボックスのアイコンと無料パックの残数を表示する。押すと「10分ごとに無料パックが1つ引けるようになる」と説明する吹き出しがアイコンの下に表示される。無料パックを選択して残りが0のときだけ、ボタンには「次の無料パックまで」と残り時間を表示し、回復するまで押せない。
- 排出率はパックごとに、枠（何枚目か）とレアリティの組み合わせで設定する。パック選択画面には排出率の表を表示しない。

## コレクション

- 総合資産ランキングで、所持・出品中のカードの合計点を競う。各コピーの点数は月間閲覧数と記事の長さから求め、取引価格は使わない。上位50人と自分の順位を表示し、同点は同順位とする。→ [総合資産ランキング](./user-stories/asset-ranking.md)

- レアリティの絞り込み列の右端で、引いた順・閲覧数順・記事サイズ順を選べる。初期表示は引いた順（新しい順）とする。
- 同じカードはまとめ、現在所持中または出品中のコピーのうち最新の作成日時を引いた順の基準とする。閲覧数・記事サイズは数値の高い順とし、記事サイズが未取得のカードは末尾に置く。同値なら引いた順、日時も同じならカード ID 順とする。レアリティの絞り込みと併用できる。

## 当たったカードの使い方

- マーケットではオークションでカードを売買する。開始価格と期間（1〜24時間、1時間単位）を決め、終了時点で最高額の入札者が落札する。残高が0ptでも入札額を入力できる。「入札」を押して残高が足りない場合は不足分を表示し、pt購入を案内する。入札額は入札が成立した時点で支払い、抜かれたら返す。
- 取引が成立すると、落札額の全額が、無償 pt として出品者に入る。
- 開始価格は10pt以上とし、初回は開始価格から入札できる。現在の最高入札額が1,000pt未満なら10pt、1,000〜4,999ptなら100pt、5,000〜9,999ptなら250pt、10,000〜49,999ptなら500pt、50,000pt以上なら1,000ptを最低上乗せ額とする。
- 入札のあるオークションは取り下げられない。終了前の残り10秒以内に入札が成立すると、その入札時点から60秒後が新しい終了時刻になる。延長後も同じ条件で再延長する。

## ゲーム内通貨（pt）

- iOSでは500pt、1,000pt、5,000ptをApp Storeで購入できる。価格はストアが現地通貨で表示する。TestFlightのテスト購入とApp Storeの購入は、同じユーザーの有償pt残高に加算する。
- 使い道は、有料パックの開封と、マーケットでのカードへの入札。
- 課金で得た有償 pt と、マーケットの売上で得た無償 pt を区別する。資金決済法の前払式支払手段として有償分の未使用残高を管理するため。
- 残高は、獲得の記録（`coin_deposit`）と、消費をどの獲得分から払ったかの記録（`coin_deposit_withdraw`）から計算する。残高だけを持つテーブルは作らない。
- 支払いは無償 pt から先に、同じ種類なら古い獲得分から使う。
- pt を現金に払い戻す機能は作らない。

## 開封の演出

開封は参考録画のような黒背景・箔袋の発光・カードの反転を中心にする。流れは次のとおり。詳細は [screens.md](./design/screens.md) の開封画面を参照。

パックの切り替え、袋を開ける瞬間、タブやカードの選択時に短い効果音を鳴らす。iOSの消音モードに従う。

1. パック選択（カルーセル）では、横にドラッグすると袋が指に追従し、指を離すと移動量と速さに応じて袋が中央に収まる。開封ボタンを押すと中央の袋を開封する。
2. 黒い背景に選んだ種類の色の箔袋が横に並ぶ。
3. 袋をタップして手前に寄せ、上端の封の好きな位置から左右どちらかに軽くなぞると、切り口の光が指に追従し、上端がちぎれて袋が開く。タップやわずかな指のずれでは開かない。対応端末では、袋を開けた瞬間に5枚のうち最も高いレアリティに応じて1回振動する。コモンのみなら微細、レアなら弱く、SRなら強く、レジェンドなら最も強く振動する。
4. 正方形の写真5枚が中央に重なる。手前の写真をタップするか左右にスワイプすると1枚めくれ、次の写真が現れる。対応端末では、先頭を含めてR以上の写真が新しく手前に出るたびに1回振動する。5枚目をめくると開封結果に進む。
5. 最後に「開封結果」として5枚を一覧で表示する

演出はスキップできる。スキップで結果に進むときは、R以上が含まれていれば最も高いレアリティに応じて1回振動する。OSの動きを減らす設定では移動・回転・拡縮・粒子・フラッシュを抑える。

抽選はサーバーで済ませてから演出を始める。演出の途中でリロードしても引き直しにはならず、開封履歴から続きを見られる。

## 法務・運営上の確認事項

- 資金決済法: 有償 pt は前払式支払手段にあたる。未使用残高が基準日に1,000万円を超えると届出と供託が必要。払い戻しは原則禁止。
- 景品表示法: 特定の組み合わせを揃えると報酬が出る仕組み（いわゆるコンプガチャ）は作らない。
- 賭博にあたらないようにする: pt やカードを現金化できる経路（RMT）を利用規約で禁止し、払い戻しも行わない。
- Wikipedia のライセンス: 本文は CC BY-SA 4.0。カード詳細には記事へのアイコンリンクを載せ、要約テキストは同じライセンスで扱う。画像は記事ごとにライセンスが異なり、フェアユースの画像は使えないため、Wikimedia Commons のフリーライセンス画像だけを使う。
- 未成年の課金上限を設ける（規約には記載済み、機能は未実装）。
- 規約類のページ: 利用規約（`/legal/terms`）、プライバシーポリシー（`/legal/privacy`）、特定商取引法に基づく表記（`/legal/tokushoho`）、資金決済法に基づく表示（`/legal/payment-services`）。運営者名・住所・連絡先などは［］の仮置きで、公開前に埋めて法務確認を受ける。
