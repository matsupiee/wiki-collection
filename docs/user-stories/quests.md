# クエストを達成してptを受け取る

> ステータス: 実装済み。APIとiOSシミュレーターで確認済み。実機は未確認。

## ストーリー

カードを集める利用者として、開封や収集の目標と進捗を確認し、達成すると自動的にptを受け取りたい。受け取り忘れを気にせず、次のパックを楽しめるとうれしい。

## 動作確認の手順

1. マイページの「クエスト」を開く。
   - 5系統・17段階の条件、進捗、報酬が表示される。開封・収集・ジャンルの各段階は異なる称号で表示され、pt履歴でも同じ称号を使う。
   - 新規ユーザーの進捗は0。参加・受け取りボタンはない。
   - 一覧を開くだけでは残高が変わらない。
2. 初めて無料パックを開封する。
   - 「パック初心者」で10無償ptが付与され、開封結果に達成件数と合計報酬が表示される。
   - R・SR・レジェンドが初めて出た場合は該当する報酬も同時に付く。上位のレアリティで下位条件は達成しない。
   - → [無料パックを開ける](./open-free-pack.md)
3. マイページのクエストとpt履歴を開く。
   - 達成した段階は「達成済み・付与済み」になる。
   - pt履歴にはクエスト名と無償ptの入金が表示される。
   - 開封結果を再表示しても残高は増えない。
4. 専用のローカルユーザーで `bun packages/db/src/seed/quests-cli.ts --user-name ゲスト名 --seed` を実行する。
   - 確認専用パックに9回・24種類・4ジャンルの履歴を追加する。既存の履歴・残高は消さない。同じコマンドを再実行しても同じ履歴は増えない。
   - 他の履歴がないユーザーなら、新しい種類・ジャンルのカードを次に引くと10回・25種類・5ジャンルの条件を同時に達成する。
5. 売却後にクエストを確認する。
   - 自分のパック開封から獲得した累計種類・ジャンルは減らない。買い手のクエストには加算されない。
   - → [オークションで売買する](./market-auction.md)
6. APIテストで同時開封と入金失敗を再現する。
   - 同じ段階の達成記録と入金は各1件だけになる。
   - 入金失敗時は開封・カード・達成記録を取り消し、無料枠を戻す。
7. 導入前の履歴がある場合、運営用コマンドで未付与の対象件数・合計ptを確認する。
   - `--apply` で過去分を付与できる。再実行しても増えない。
   - 一括付与前は「条件達成・次回開封時に自動付与」と表示され、次回の通常開封でも付与される。

## データの持ち方

- クエスト定義はサーバー側のコードで管理する。
- 進捗は `pack_opening`・`pack_opening_card`・`card` から求める。
  - 売買で変わる現在の所有者や所有権履歴のreasonからは集計しない。
- `user_quest_completion` はユーザー・段階ごとに一意の達成記録を持つ。
- `coin_deposit.quest_completion_id` は達成記録ごとに一意とし、無償の `quest_reward` を記録する。
  - 開封結果の保存、条件判定、達成、入金は同じbatchで確定する。画面の演出完了を待たない。
