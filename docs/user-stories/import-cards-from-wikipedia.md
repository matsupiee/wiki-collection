# Wikipedia の記事をカードとして取り込む

> ステータス: ローカルの D1 への取り込みは実装済み。本番の D1 への取り込み（定期実行）は未実装。

## ストーリー

運営者として、ジャンルごとのカテゴリから Wikipedia の記事を集めて、カードとしてまとめて追加したい。
1枚ずつ手で作らずに済み、カードにしにくい記事は自動で外れるので、少ない手間でカードを増やせる。

## 動作確認の手順

Wikipedia の API に接続できる環境で行う。

1. `bun run db:seed` を実行する。
   - サンプルのカード 60 枚と、その閲覧数から決めたレアリティの下限（`rarity_threshold`）が入る。
2. `bun run wiki:import --genre space --max 30` を実行する。
   - 宇宙ジャンルのカテゴリ「天文学」とその1段下のサブカテゴリから、最大 30 件の記事を調べる。
   - 追加したカードと、除外した記事とその理由が一覧で出る。
   - 曖昧さ回避、一覧記事、存命人物、事件・事故、要約が短い記事はカードにならない。
   - seed で下限が入っているので、「レアリティの下限を決めました」とは出ない。
3. もう一度同じコマンドを実行する。
   - 前回カードにした記事は取り直さず、追加されない。
4. `bun run dev:local` で起動し、取り込んだカードを手に入れたユーザーでカード詳細を開く。
   - 要約は記事冒頭の文章になっている。
   - 出典の行に「取り込んだ時点の版」のリンクが出て、押すとその版の記事が開く。
   - 画像があるカードは、作者とライセンス（Wikimedia Commons）が出る。画像が使えない記事は、ジャンルの色とタイトルの1文字目で絵柄が出る。
   - → [集めたカードと図鑑を見る](./collection-and-dex.md)
5. `rarity_threshold` が空の D1（本番の初回など）で取り込む。
   - 取り込んだ記事の閲覧数の順位から下限が決まり、「レアリティの下限を決めました」と下限の値が出る。
   - 以降の取り込みは、その下限でレアリティを決める。

## データの持ち方

- `card`: 取り込んだ記事1件につき1行。
  - `(wikiLang, wikiPageId)` の unique 制約で、同じ記事を二重にカードにしない。
  - `wikiRevisionId` と `wikiFetchedAt` に、要約を取った時点の版と日時を持つ。CC BY-SA の帰属表示に使う。
  - レアリティ、要約、閲覧数は取り込んだ時点で固定する。
- `rarity_threshold`: レアリティごとの月間閲覧数の下限。
  - 最初の取り込み（ローカルでは seed）で決め、カードと同じ batch で保存する。
